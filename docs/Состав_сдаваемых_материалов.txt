СОСТАВ СДАВАЕМЫХ МАТЕРИАЛОВ
Хакатон «Разработка ИИ-агента для автоматизированной проверки функций
информационной безопасности в процессе разработки программного обеспечения
с интеграцией в CI/CD»
Организатор: ТОО «KMG Digital»


1. ЧТО СДАЁТ КОМАНДА

1.1. Ссылка на репозиторий с решением. Репозиторий должен содержать:
     - исходный код Агента;
     - используемые системные подсказки (промпты) и (или) описания навыков;
     - файлы конфигурации пайплайна, обеспечивающие запуск Агента отдельным
       шагом;
     - инструкцию по запуску (README), достаточную для того, чтобы Экспертная
       комиссия воспроизвела проверку самостоятельно: команды запуска,
       переменные окружения, требуемые ключи доступа к модели, ожидаемый
       результат.

1.2. Отчёт Агента о проверке Тестового проекта в двух форматах:
     - машиночитаемый JSON;
     - представление в формате Markdown для чтения специалистом.
     Состав отчёта — по пункту 4.6 Технического задания: по каждому нарушению
     идентификатор и формулировка Требования ИБ, путь к файлу и номер строки
     (либо имя функции, класса, параметра), фрагмент кода, обоснование, уровень
     критичности, рекомендация по устранению; сводная часть — идентификатор
     коммита, дата и время начала и завершения проверки, длительность, общий
     результат, количество нарушений и статус по каждому Требованию ИБ,
     включая те, по которым нарушений не выявлено.

1.3. Журнал (лог) выполнения шага проверки в пайплайне — текстом или
     снимком экрана. Из журнала должны быть видны код завершения, количество
     выявленных нарушений и перечень нарушенных Требований ИБ.

1.4. Краткое описание подхода, 1–2 страницы:
     - архитектура решения и используемая модель (LLM);
     - применённые методы анализа;
     - механизм обеспечения полноты анализа по пункту 4.4.4 Технического
       задания: как Агент анализирует проект целиком, а не только изменённые
       файлы, и что делает при ограничении объёма контекста модели;
     - известные ограничения решения.

1.5. Сведения о ресурсах: время выполнения одной проверки и примерный расход
     токенов. Время выполнения шага проверки не должно превышать 30 минут
     (пункт 4.7.1 Технического задания).

1.6. Идентификатор коммита Тестового проекта, на котором выполнена проверка.
     Он же должен быть указан в сводной части отчёта Агента.


2. ПОРЯДОК И СРОКИ

2.1. Материалы направляются Организатору не позднее чем за один час до начала
     защиты, одним архивом или ссылкой на папку с доступом для Экспертной
     комиссии.

2.2. Если какой-либо из материалов отсутствует, об этом следует сообщить прямо
     при сдаче. Отсутствующий материал оценивается как непредставленный.

2.3. Материалы, представленные после начала защиты, к оценке не принимаются.


3. НА ЧТО ОБРАТИТЬ ВНИМАНИЕ

3.1. Проверка должна выполняться без участия человека. Агент не должен
     запрашивать ввод во время работы и не должен вносить изменения в
     проверяемый репозиторий.

3.2. Результат проверки должен управлять пайплайном: при отсутствии нарушений
     код завершения 0 и продолжение выполнения, при наличии нарушений — код 1
     и блокировка слияния и развёртывания.

3.3. Аварийное завершение Агента (код завершения 2 — недоступность модели,
     превышение лимитов, ошибка разбора проекта) означает, что проверка не
     выполнена. Такой результат засчитывается как непрохождение проверки.

3.4. Дефекты, не относящиеся к Требованиям ИБ перечня пункта 4.5 Технического
     задания, приводятся в отчёте отдельно и не являются основанием для
     прерывания пайплайна (пункт 4.8.1 Технического задания).

3.5. Отчёт не должен содержать паролей, ключей, токенов и иных секретов.
