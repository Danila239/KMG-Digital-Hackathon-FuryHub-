## Живая модель: проверка не завершена

OpenRouter подтвердил валидность ключа через endpoint состояния. При генерации провайдер ModelRun возвращает HTTP 429 (temporarily rate-limited upstream). Последний `scan` остановился на первом пакете с кодом 2: `reports/demo/20260924T153823Z-b96d198d/run-status.json`. Manifest сохранен, модельное покрытие равно нулю; итоговый отчет соответствия не сформирован. В более раннем запуске также был HTTP 400; транспортная JSON-схема после этого упрощена до типов и enum, а все ограничения по-прежнему проверяются локально. После этой правки успешно обработаны два структурированных ответа в evaluate; полный обзор большого проекта не завершен. Два завершенных ответа модели получены при evaluate; повторный doctor после них не выполнялся. Проверка ключа отдельно от генерации не означает доступную мощность или квоту выбранной модели.

Пока нет завершенного живого анализа цели и полной live-оценки всех 16 fixtures. Частичный прогон: `reports/evaluation/20260924T153626Z-c9b919e1/evaluation.json`, код 2, два верных случая, 8130 токенов в двух успешных ответах API. Эти числа не включают неизвестные затраты неуспешных запросов. Нельзя утверждать, что модель нашла нарушения в основном KMG-проекте, выдержала все приемочные критерии или уложилась в бюджет полного анализа. Следующий подтверждающий результат — успешный `doctor`, затем артефакты законченного `scan` и отдельного `evaluate`.

Файл workflow и локальная проверка его синтаксиса не являются доказательством запущенного GitHub Actions pipeline. Публикация CI, secrets и required checks подтверждаются отдельно живым run.

## Что остается до приемки демки

1. Получить успешный `doctor` от выбранного Qwen endpoint.
2. Выполнить весь `scan`, проверить находки и их контраргументы на исходниках.
3. Закончить `evaluate` на 16 примерах и измерить ошибки модели.
4. Подтвердить CI gate живым GitHub Actions run после настройки Actions secret. Пользователь поручил опубликовать обе папки одним репозиторием.

## Объединение для командной работы

Обе папки находятся в одном репозитории; активный workflow расположен в корне. Локальные отчеты прошлых прогонов намеренно не включаются в Git, их пути выше документируют локальные проверки. Секретов в публикации нет. Исходная версия upstream сохранена в корневом README; новые отчеты используют SHA общего репозитория.

После объединения дополнительно пройдены регрессии Git-метаданных подпапки: изменения соседнего агента не меняют dirty цели; изменения целевых файлов учитываются; исключенные секреты не читаются. Полный локальный прогон: 62 теста, успешно.
