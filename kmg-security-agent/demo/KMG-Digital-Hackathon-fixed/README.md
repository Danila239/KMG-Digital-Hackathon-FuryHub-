# Система обработки обращений

Локальное веб-приложение службы поддержки: обращения, очереди, комментарии, файлы, пользователи и выгрузки. Требования к системе приведены в [технической спецификации](docs/Техническая_спецификация_ИС_обработки_обращений_КМГ.docx).

## Установка и запуск

Требуется Windows x64 и Python 3.14. Распакуйте проект в отдельный каталог. В PowerShell из каталога проекта:

```powershell
python -m venv .venv
if (Test-Path requirements.lock) {
    .venv/Scripts/python.exe -m pip install --require-hashes -r requirements.lock
} else {
    .venv/Scripts/python.exe -m pip install -r requirements.txt
}
.venv/Scripts/python.exe setup_local.py
.venv/Scripts/python.exe manage.py seed_workload
.venv/Scripts/python.exe serve.py
```

Откройте `https://127.0.0.1:<https_port>`, где `https_port` указан в `proxy.json`. При необходимости задайте свободные порты переменными `HELPDESK_HTTP_PORT`, `HELPDESK_HTTPS_PORT`, `HELPDESK_BACKEND_PORT` до запуска. Все слушатели ограничены 127.0.0.1. Ctrl+C завершает сервер и сборщик.

Сертификат создаётся локально. Подтвердите доверие только этому сертификату для своего стенда; не отключайте проверку сертификатов глобально. Внешняя почта и облачные подключения для запуска не нужны.

`setup_local.py` создаёт ключи, сертификат, базу, начальные записи и статику. Рабочие данные находятся в `runtime/`; для независимого экземпляра задайте `HELPDESK_RUNTIME` перед инициализацией и запуском. Используйте новый рабочий каталог. Повторный запуск настройки сохраняет существующие обращения и пароли.

## Начальные учётные записи

| Логин | Пароль | Роль |
|---|---|---|
| applicant | Training-2026!applicant | Заявитель |
| operator | Training-2026!operator | Оператор |
| administrator | Training-2026!administrator | Администратор |

Учётные записи и обращения синтетические. Очередь «Рабочие места» открыта для подачи вошедшим заявителем и назначена оператору. Очередь «Сетевая инфраструктура» не назначена начальному оператору. Используйте стенд только локально и не загружайте реальные персональные данные.

## Наполнение рабочими данными

После `setup_local.py` и до запуска сервера выполните:

```powershell
.venv/Scripts/python.exe manage.py seed_workload
```

Команда создаёт дополнительный набор за 180 дней до начала текущего дня:

- 72 заявителя, 12 операторов и 1 администратора; начальные 3 учётные записи остаются;
- 8 очередей в сумме: рабочие места, сеть, почта, приложения, доступ, оборудование, контроль событий и удалённая работа;
- 600 дополнительных обращений: новые, повторно открытые, решённые, закрытые и дублирующие; пять уровней приоритета, сроки, просроченные и отложенные заявки;
- несколько тысяч записей переписки, внутренние заметки специалистов, история назначения и изменения статусов;
- вложения TXT, PNG и PDF: карточки диагностики, графики наблюдения и акты проверки. Часть файлов относится к внутренним заметкам.

В свежем экземпляре после обеих команд будет 88 пользователей, 8 очередей, 603 обращения, 2 883 записи переписки, 1 200 записей истории изменений и 250 вложений (116 TXT, 67 PNG, 67 PDF). Имена, адреса, подразделения и устройства вымышленные. Все email используют `example.test`. Внешняя почта не отправляется. Файлы создаются локально, дополнительные пакеты и загрузки из Интернета сидеру не нужны. Журналы аудита отражают реальное время импорта; даты истории обращений моделируют предыдущие месяцы.

### Вход и распределение работы

| Учётные записи | Пароль | Назначение |
|---|---|---|
| `sample.requester01` … `sample.requester72` | `Service-2026!` + полный логин | Заявители |
| `sample.operator01` … `sample.operator12` | `Service-2026!` + полный логин | Операторы |
| `sample.admin01` | `Service-2026!sample.admin01` | Администратор |

Например, пароль `sample.operator01`: `Service-2026!sample.operator01`. Это открыто описанные синтетические аккаунты локального стенда. Пароли сохраняются через штатное хеширование. Повторное заполнение не сбрасывает изменённые пароли.

| Операторы | Назначенные очереди |
|---|---|
| 01, 09 | Рабочие места; Сетевая инфраструктура |
| 02, 10 | Сетевая инфраструктура; Почта и календарь |
| 03, 11 | Почта и календарь; Корпоративные приложения |
| 04, 12 | Корпоративные приложения; Учётные записи и доступ |
| 05 | Учётные записи и доступ; Офисное оборудование |
| 06 | Офисное оборудование; Контроль событий |
| 07 | Контроль событий; Удалённая работа |
| 08 | Удалённая работа; Рабочие места |

Операторы имеют роль `operator` и признак `staff`, администратор — роль `administrator` и признак `staff`. Сидер не создаёт `superuser`. Заявители не имеют `staff`. Назначения очередей выдаются явно при создании оператора. Существующие роли и назначения автоматически не исправляются. Обращения во внутренних очередях сети и контроля событий зарегистрированы специалистами; остальные — заявителями. Исходному пользователю `applicant` также добавляется часть обращений. Некоторые новые заявители пока не имеют обращений.

### Размер, воспроизводимость и повторный запуск

```powershell
# Увеличить общее число обращений набора до 1200
.venv/Scripts/python.exe manage.py seed_workload --tickets 1200

# Для нового runtime: 900 обращений за год на фиксированную дату
.venv/Scripts/python.exe manage.py seed_workload --tickets 900 --days 365 --seed 42 --as-of 2026-09-01
```

`--tickets` задаёт целевой размер набора (1–3000), а не число записей, добавляемых при каждом вызове. Значение по умолчанию — 600; исходные 3 обращения в это число не входят. Уменьшение параметра ничего не удаляет. Повторный вызов пропускает существующие обращения целиком, включая изменённые студентом заголовки, комментарии и статусы. Удалённые обращения набора при следующем заполнении создаются заново. Сторонние обращения не изменяются.

Дата, глубина истории и число `--seed` сохраняются в `runtime/seeds/workload.json`: при повторе их можно не указывать. Изменение этих параметров для уже начатого набора отклоняется. Одинаковые параметры дают одинаковые деловые сценарии; идентификаторы, криптографические ключи, хеши паролей и аудит между экземплярами различаются. После прерывания можно повторить команду: завершённые обращения сохраняются, незавершённое будет создано заново. Одновременные запуски сидера в одном runtime запрещены блокировкой.

Если роли или активность пользователей набора изменены, либо очередь осталась без назначенного оператора набора, заполнение останавливается с пояснением. Для независимого набора выберите новый пустой каталог, сохранив прежний:

```powershell
$env:HELPDESK_RUNTIME = Join-Path $PWD 'runtime-second'
.venv/Scripts/python.exe setup_local.py
.venv/Scripts/python.exe manage.py seed_workload --tickets 600
.venv/Scripts/python.exe serve.py
```

Переменная должна оставаться одинаковой для настройки, сидера, сервера и сборщика. Запускайте заполнение при остановленном сервере. Импорт с хешированием паролей, шифрованием файлов и аудитом может занять несколько минут; прогресс выводится каждые 100 обращений. Общие лимиты пользователей и обращений проверяются перед созданием данных. База, ключи и файлы рабочего экземпляра не входят в архив проекта.

### Что проверить в интерфейсе

1. Войти как `sample.requester03`, найти свои обращения, открыть переписку и скачать доступное вложение. Для поиска подходят слова «принтер», «VPN», «отчёт», названия отделов и номера устройств вида `WS-017`.
2. Войти как `sample.operator01`, просмотреть работу в назначенных очередях, прочитать внутренние заметки, ответить и изменить статус обращения.
3. Войти как `sample.admin01`, просмотреть пользователей и обращения, выполнить CSV- и JSON-выгрузки.
4. Повторить `seed_workload` с тем же размером: число новых пользователей и обращений должно быть нулевым, сделанные изменения должны сохраниться.

## Проверка запуска

```powershell
.venv/Scripts/python.exe manage.py check
.venv/Scripts/python.exe manage.py test portal
.venv/Scripts/python.exe collector.py --once
```

Встроенный тест проверяет базовый сценарий работы. Он не заменяет проверку требований безопасности. Контракт маршрутов и правила доступа приведены в спецификации. Исходный код приложения расположен в `portal/`, библиотечные компоненты — в `src/helpdesk/`, активная конфигурация — в `demodesk/config/`.
