# ИБ-01: Разграничение доступа к административному функционалу

Доступ к административному интерфейсу должен предоставляться исключительно пользователям с ролью «администратор». Проверка роли должна выполняться на стороне сервера при каждом обращении. Сокрытие элементов административного интерфейса на стороне клиента не является выполнением требования.

Порядок проверки:

1. Определить достижимые административные интерфейсы и операции по маршрутам, вызовам и назначению, включая альтернативные API.
2. Проследить серверную авторизацию через декораторы, middleware, общие helpers и вызываемые сервисы.
3. Проверить, что допустима именно бизнес-роль администратора; технические флаги эквивалентны ей только при доказанном инварианте назначения.
4. Проверить создание пользователей, смену ролей и прав, управление очередями и сброс учетных данных, если это административные функции проекта.
5. Для отсутствующей проверки указать конкретную достижимую операцию и обследованную цепочку; не делать вывод по одному имени функции.

Контраргумент: операторский интерфейс сам по себе не административный. Проверь назначение конкретной операции. Для общего role helper процитируй и его реализацию, и место подключения. Полномочия администратора нельзя заключать только из имени поля, но нельзя и отрицать доказанный инвариант сопоставления роли.

Находка требует точной цитаты достижимого участка и обоснования связи с этим требованием. При межфайловой защите или обходе приведи несколько evidence. Не считай отсутствующий в текущем пакете файл доказательством отсутствия механизма во всем проекте. В focused review оценивай только этот ИБ-ID.
