# ИБ-04: Криптографическая защита персональных данных при хранении

Персональные данные (фамилия, имя, отчество, логин, адрес электронной почты, пароль) должны храниться с применением криптографической защиты с параметрами не ниже уровня, установленного СТ РК 1073-2007. Пароли должны храниться в виде значений функций формирования ключа bcrypt, argon2 или scrypt. Открытые пароли и быстрые хеш-функции общего назначения без адаптивного алгоритма не допускаются.

Порядок проверки:

1. Проследить персональные поля от входа до физического хранения, включая копии, сериализацию и альтернативные пути записи.
2. Отдельно проверить пароли: фактические hashers, индивидуальную соль, параметры стоимости, создание, смену, сброс и начальное заполнение.
3. Проверить реальное шифрование остальных персональных полей и применимые параметры; ограничение доступа и кодирование не заменяют шифрование.
4. Различать шифрование отдельных вложений, отдельных полей и базы целиком; защита одного объекта не доказывает защиту остальных.
5. Проследить генерацию и хранение ключей; не требовать предъявления сертификатов в рамках статического анализа и не утверждать сертификацию по названию алгоритма.

Контраргумент: обычное строковое поле ORM может храниться внутри реально зашифрованной базы, а адаптивный password hasher может задаваться централизованно. Проследи backend и настройки прежде, чем сообщать открытое хранение. Base64, маска интерфейса и хеш общего назначения не являются заменой необходимой криптографической защиты.

Находка требует точной цитаты достижимого участка и обоснования связи с этим требованием. При межфайловой защите или обходе приведи несколько evidence. Не считай отсутствующий в текущем пакете файл доказательством отсутствия механизма во всем проекте. В focused review оценивай только этот ИБ-ID.
