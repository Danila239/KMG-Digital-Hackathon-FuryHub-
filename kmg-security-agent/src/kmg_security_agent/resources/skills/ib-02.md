# ИБ-02: Проверка сессии и токена на стороне сервера

Валидность сессии и (или) токена должна проверяться на стороне сервера при каждом обращении к защищенным конечным точкам, включая программные интерфейсы (API).

Порядок проверки:

1. Сопоставить маршруты с чувствительными данными и действиями; отделить намеренно общедоступные ресурсы.
2. Проследить общую проверку сессии или токена до доступа к данным, включая альтернативные входы.
3. Проверить подпись, срок действия и применимые условия валидности токена или сессии по реализации и контракту.
4. Проверить существование и активность субъекта, если они являются условиями валидности учетной записи.
5. Не считать CSRF-токен, скрытую кнопку или наличие поля Authorization достаточным доказательством аутентификации.

Контраргумент: публичный healthcheck, login или статический ресурс не требуют пользовательского токена. Сначала докажи чувствительность защищаемого ресурса. JWT, Django session и самописные токены имеют разные цепочки проверки; достаточно одного корректного механизма, если он обязателен для каждого запроса.

Находка требует точной цитаты достижимого участка и обоснования связи с этим требованием. При межфайловой защите или обходе приведи несколько evidence. Не считай отсутствующий в текущем пакете файл доказательством отсутствия механизма во всем проекте. В focused review оценивай только этот ИБ-ID.
