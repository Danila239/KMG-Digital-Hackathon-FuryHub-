# ИБ-03: Защита канала передачи данных

Обмен данными между клиентом и сервером должен осуществляться исключительно по протоколу TLS версии не ниже 1.2 с применением стойких шифронаборов. Конфигурации, допускающие передачу данных в незащищенном виде, устаревшие версии протокола или слабые шифронаборы, являются нарушением.

Порядок проверки:

1. Найти фактические клиентские точки входа, транспортный модуль, параметры запуска и значения конфигурации по умолчанию.
2. Проверить запрет передачи чувствительных данных по HTTP и путь перенаправления до обработки запроса.
3. Проверить минимальную версию TLS и разрешенные наборы шифров; различать реально разрешенный набор и неиспользуемый пример.
4. Учитывать границу reverse proxy: внутренний loopback-канал не является нарушением, если он разрешен спецификацией и не является клиентской точкой доступа.
5. Не выводить наличие TLS из имени порта; сопоставить настройки cookie, proxy trust и проверки сертификата с реальным путем запроса.

Контраргумент: разрешенный внутренний канал reverse proxy на loopback не равен клиентскому HTTP. Не путай дату появления шифронабора с фактически разрешенной версией протокола. Стойкость и достижимость оценивай совместно; отдельный тестовый пример не становится активной серверной конфигурацией без связи с запуском.

Находка требует точной цитаты достижимого участка и обоснования связи с этим требованием. При межфайловой защите или обходе приведи несколько evidence. Не считай отсутствующий в текущем пакете файл доказательством отсутствия механизма во всем проекте. В focused review оценивай только этот ИБ-ID.
